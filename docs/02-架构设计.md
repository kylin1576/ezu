## 1. 技术栈总览

| 层 | 选型 | 说明 |
|----|------|------|
| 语言/框架 | JDK 21 + Spring Boot 4.1 | 虚拟线程；与 spring-ai 2.0.1 配套 |
| ORM | MyBatis-Plus | 主键雪花 ID（`ASSIGN_ID`） |
| 业务库 | MySQL 8 | |
| 缓存 | Redis 7 | 会话、验证码、商品缓存、分布式锁 |
| 认证 | Sa-Token | **双账号体系**：C 端（openid）+ B 端（账号密码 RBAC） |
| AI | spring-ai 2.0.1 + 智谱 GLM（OpenAI 兼容端点） | chat / stream(SSE) / tool calling |
| 向量库 | 一期：`SimpleVectorStore`（内存）；**规划：PostgreSQL + pgvector（当前无 PG 环境，依赖与配置注释预留）** | VectorStore 为抽象接口，切换只改配置 |
| 用户端 | uni-app + Vue3 + TS + pinia | 一套代码编译微信 + 支付宝双小程序 |
| 管理后台 | Vue3 + Vite + Element Plus（soybean-admin 模板） | 现成 RBAC/布局/主题 |
| 部署 | docker-compose（mysql / redis / app） | pgvector 服务注释预留 |

## 2. 后端工程结构（Maven 多模块单体）

个人项目不上微服务，单进程多模块：

```
ezu/
├── ezu-common        # 统一响应/异常/工具/实体基类（无业务）
├── ezu-admin         # B端：后台账号、RBAC、操作日志
├── ezu-user          # C端：小程序用户、认证、地址
├── ezu-product       # 品类、SPU/SKU、租金方案、SN 设备台账
├── ezu-order         # 订单、租约、押金记录、账单、物流
├── ezu-payment       # 支付抽象层
│                      #   PaymentChannel 接口
│                      #   一期：MockChannel（模拟支付）
│                      #   二期：AlipayChannel（信用免押/真实支付），只加实现不改调用方
├── ezu-ai            # Agent、RAG、知识库管理、会话记录
└── ezu-startup       # 启动聚合 + 配置（唯一可运行模块）
```

### 2.1 分层约定（沿用 light-supplyhub 惯例）

```
Controller → ApplicationService → DomainService → Repository → Mapper
```

- Controller：HTTP 请求响应、参数校验（`@Validated`）
- ApplicationService：业务编排、事务（`@Transactional`）
- DomainService：核心业务逻辑、领域计算
- Repository 继承 ServiceImpl，Mapper 继承 BaseMapper
- XML 映射：`src/main/resources/mapper/{模块}/{Mapper}.xml`

### 2.2 模块间调用

- 正向依赖：直接注入被依赖模块的 DomainService（如 `ezu-order` → `ezu-product`）
- 反向依赖：被依赖模块定义 `Acquire*Interfaces` 接口，依赖方模块实现（如 `ezu-product` 定义 `AcquireOrderInterfaces`，`ezu-order` 实现，供商品侧查设备占用）

## 3. 认证方案（Sa-Token 双账号体系）

| 端 | 登录方式 | 账号标识 | 隔离方式 |
|----|---------|---------|---------|
| C 端小程序 | 微信/支付宝 `uni.login` → code 换 openid → 绑定手机号 | `t_user.id` | 独立登录入口（`/api/app/**`），StpUtil 不同 loginType |
| B 端后台 | 账号密码 + RBAC | `t_admin_user.id` | 独立登录入口（`/api/admin/**`） |

## 4. 支付抽象（预留支付宝信用）

```java
public interface PaymentChannel {
    PaymentResult pay(PaymentRequest request);          // 支付/冻结押金
    RefundResult refund(RefundRequest request);          // 退款/解冻
}
```

- 一期注册 `MockChannel`：直接落库成功，模拟支付回调
- 二期注册 `AlipayChannel`：芝麻信用免押 + 真实支付，**只新增实现类，调用方代码不动**
- 渠道路由存 `t_payment_record.channel`，回调统一入口 `POST /api/callback/payment/{channel}`

## 5. AI 架构（ezu-ai 模块）

```
小程序聊天页（SSE 流式 /api/app/ai/chat）
   ↓
ChatAgent（spring-ai ChatClient）
   ├─ ChatMemory：会话记忆（conversationId = 用户维度）
   ├─ RAG：知识库检索（FAQ/设备文档/租赁规则 → VectorStore 相似度 top-k → 上下文注入）
   └─ Tool Calling（spring-ai @Tool）：
       ├─ searchProduct(关键词/用途/预算)   → 查商品+租金+库存
       ├─ queryMyOrder(状态筛选)            → 查当前用户订单
       └─ recommendProduct(场景描述)         → 规则+向量混合推荐
后台 AI 管理：知识库 CRUD + 文档上传→分段→向量化入库 + 会话记录查询
```

| 项 | 决策 |
|----|------|
| 模型 | 智谱 `glm-4.5-flash`（开发期免费额度），上线可配置切换 |
| 向量库 | 一期 `SimpleVectorStore`（内存，重启丢失可重建，开发够用）；**pgvector 为规划项，当前无 PG 环境，依赖与配置以注释形式预留** |
| 知识库源数据 | `t_ai_knowledge_doc` 管源文档与分段，向量重建有据可依 |

## 6. 关键设计决策记录

| # | 决策 | 理由 |
|---|------|------|
| 1 | SN 序列号级库存（非纯数量库存） | 自营租赁资产闭环的核心；电商数量库存无法追溯单台设备 |
| 2 | SPU/SKU 与 SN 分离 | SKU 管定价与展示（可无限上架），SN 管实物资产（一台一行） |
| 3 | 下单快照冗余商品名/图/租金单价 | 防后续改价/改图影响历史订单展示与结算 |
| 4 | 订单锁定具体 SN（锁定态） | 下单未发货期间该设备不可被他人下单 |
| 5 | 多模块单体，不上微服务 | 个人项目单机部署，模块化保清晰边界即可 |
| 6 | 押金记录独立流水表 | 冻结/退还/扣除全程可审计 |
| 7 | 逻辑删除用常规语义（0=未删，1=已删） | 新项目从零开始，不沿用历史反直觉约定 |
| 8 | PG 向量库注释预留 | 当前无 PG 环境；VectorStore 抽象保证后续切换零改代码 |

## 7. 部署形态

```yaml
# docker-compose.yml（规划）
services:
  mysql:    # 业务库
  redis:    # 缓存/会话/锁
  app:      # ezu-startup 打包的 jar
  # pgvector:  # 【预留，当前注释】向量库：pgvector/pgvector:pg16
```

- 小程序端无需部署（微信/支付宝平台托管）
- 管理后台静态构建产物由 nginx 或 app 内置静态资源托管
