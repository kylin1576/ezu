# M3d：管理后台（ezu-console）实装计划

> 2026-11-12 制定。前置：M3a 后端核心闭环（8 Controller / 26 管理端接口已就绪）、M3b/M3c C 端小程序已完成。本计划完成后 M3 里程碑（资产闭环可演示）收口。

## Context

- ezu-console 现状 = M2 模板初始化原样（soybean-admin 2.3.0，views 只有 `_builtin` + `home`，service 只有模板 auth/route，`.env` 指 Apifox mock）。**业务页面 0%**。
- 后端已就绪：`/api/admin/**` 下 8 Controller 26 接口（详见下文契约摘要），管理员账号 `admin/admin123` 启动幂等初始化。
- 权限：t_permission 菜单树 5 目录 / 7 菜单 / 11 按钮码，`GET /api/admin/auth/info` 返回扁平 `permissions[]`，**无菜单树查询接口** → 前端本地路由表 + 权限码过滤（soybean 方案 A：static 路由模式）。

## 一、对接决策（模板 → ezu 后端适配）

| 项 | 模板默认 | ezu 后端实际 | 改动位置 |
|---|---|---|---|
| 成功码 | `'0000'` | `200`（HTTP 恒 200，信封 `{code,msg,data}`） | `.env` VITE_SERVICE_SUCCESS_CODE |
| 登出码 | `8888,8889` | `401`（未登录/过期） | `.env` VITE_SERVICE_LOGOUT_CODES |
| 弹窗登出码 | `7777,7778` | 无 → 置不可达值 | `.env` |
| 过期刷新码 | `9999,9998,3333`（refreshToken 单飞重发） | 无 refreshToken → 置不可达值，401 直接踢登录 | `.env` |
| token header | `Authorization: Bearer xxx` | `ezu-token: <token>`（Sa-Token 裸值） | `src/service/request/index.ts` onRequest |
| mock 残留 | `apifoxToken` 硬编码 header | 删除 | 同上 |
| baseURL | Apifox mock | dev 代理 → `http://localhost:9000` | `.env.test` + `build/config/proxy.ts`（Y 开关已有） |
| 登录接口 | `POST /auth/login {userName,password}` | `POST /api/admin/auth/login {username,password}` | `src/service/api/auth.ts` |
| 用户信息 | `GET /auth/getUserInfo` | `GET /api/admin/auth/info`，字段映射 `username→userName`、`permissions→buttons`、补 `realName` | `auth.ts` + `src/typings/api/auth.d.ts` |
| 分页结构 | useTable 期望 `{data,pageNum,pageSize,total}` | 后端 `PageVo = {total,list}`，请求 POST body `{pageNum,pageSize,...}` | api 层统一 `toPageData()` 适配函数 |
| 按钮权限 | `useAuth().hasAuth(code)`（基于 buttons） | `permissions[]` 映射到 buttons，直接复用 | 无需改动 |

**路由模式决策：保持 `VITE_AUTH_ROUTE_MODE=static`**（方案 A）。理由：后端无菜单树接口；一期角色只有超管，菜单不做角色过滤（meta.roles 留空），按钮级用 `hasAuth('spu:save')` 等控制，与 t_permission 按钮码一一对应。

## 三、任务分解

### T1 请求层对接真后端 + 登录闭环
改动：
- `.env`：成功码/登出码/弹窗码/过期码按上表调整
- `.env.test`：`VITE_SERVICE_BASE_URL=http://localhost:9000`
- `src/service/request/index.ts`：删 apifoxToken；onRequest 改发 `ezu-token`
- `src/service/api/auth.ts`：三个接口对齐（fetchRefreshToken 删除）；类型 `src/typings/api/auth.d.ts` 同步
- `src/store/modules/auth/index.ts`：去掉 refreshToken 存储分支
- 登录页 `modules/pwd-login.vue`：清演示账号提示，默认填 `admin`
- 新增 `src/service/api/helpers.ts`：`toPageData()` 分页适配

验收：起后端（9000）+ `pnpm dev`，admin/admin123 能登录进 home，F12 确认请求带 `ezu-token`；手动改坏 localStorage token 后任意请求被 401 踢回登录页。

### T2 路由骨架 + 菜单
- 建 9 个 views 目录（占位 index.vue），dev 自动重生成路由（或 `pnpm gen-route`）
- `routes.ts` 补 meta：icon（mdi 系）/order（对齐 t_permission sort：system 10 / product 20 / device 30 / order 40 / member 50）
- i18n：`zh-cn.ts`/`en-us.ts` route 段补 9 个 key（en 用简译）
- home 精简为工作台占位

验收：登录后侧边栏出现 5 目录 7 菜单 + 工作台，点击全部可跳转空页。

### T3 系统管理（账号 + 角色）
- `service/api/system.ts`：账号 list/save、角色 list/save
- 账号页：useNaivePaginatedTable + 搜索（username/realName/status）+ operate 抽屉（username/realName/phone/password/status/roleIds 多选，角色选项 `pageSize:-1` 拉全量）
- 角色页：列表 + 抽屉（name/code/remark/status）；页面上注明「权限绑定需二期」
- 按钮挂 `hasAuth('user:save')` / `hasAuth('role:save')`

验收：新增账号 → 退出 → 新账号可登录；角色可增改。

### T4 品类管理
- `service/api/product.ts`（品类部分）：tree/save/delete
- 树表格（NDataTable `rowKey=id` + children）+ 抽屉（parentId 下拉取树、name/icon/sort/status）+ 删除二次确认（拦截错误弹 msg）

验收：建两级品类 → C 端商品列表刷新可见（联调）；删除被引用品类报业务提示。

### T5 商品 SPU（最复杂，独立编辑页）
- `service/api/product.ts`（SPU 部分）：list/detail/save/shelf
- 列表页：筛选 + 批量选择上下架（BatchOperateResultVo 展示 success/skipped）+ 「新增商品/编辑」跳编辑页
- 编辑页 `/product/spu/edit?id=`：基本信息卡 + SKU 卡（动态行：specName/deposit/buyoutPrice + 内嵌租金方案子表 unit 下拉(日/周/月/季)/price/minDays）+ 参数卡（name/value/sort 动态行）+ 整体保存
- 编辑进入先 `detail/{id}` 回填

验收：新建含 2 SKU×2 方案的商品 → C 端可浏览下单；上下架后 C 端列表隐藏。

### T6 设备台账 + 采购入库
- `service/api/device.ts`：list/detail/inbound/check/repair/scrapped
- 台账：状态筛选（6 态 tag）+ keyword + 详情抽屉（Tab：基本信息/质检报告/维修记录）+ 三个操作抽屉（验机 type 按 context、维修 endDate 非空=完成、报废确认）
- 入库页：SKU 下拉（spu list pageSize:-1 取 sku）+ 可增删行表格（sn/purchaseDate/purchasePrice/purchaseChannel/conditionLevel/remark）+ 批量提交展示生成的设备编号

验收：入库 2 台 → 台账在库；对在租订单归还验收后设备状态流转正确。

### T7 订单管理
- `service/api/order.ts`：list/detail/ship/returnSign/acceptCheck/acceptConfirm
- 列表：筛选（orderNo/status/createTime 区间/overdue）+ 状态 NTag 色阶 + 详情抽屉（订单信息/商品快照/收货人/金额）
- 行操作按状态显隐：20→发货（物流公司/单号抽屉）、50→归还登记、60→验收（pass 直接完成 / 走 acceptConfirm）
- 按钮挂 `hasAuth('order:ship')` / `hasAuth('order:accept')`

验收：C 端下单 → console 发货 → C 端确认收货/申请归还 → console 验收确认 → 押金退还流水落库（查库）。

### T8 用户列表 + 收口
- `service/api/member.ts`：list
- 只读列表（nickname/phone/status 筛选）
- 全量 `pnpm typecheck` + `pnpm build` 通过；代码审查（CRITICAL/HIGH 必修）

## 五、风险与不做

**不做（一期）**：财务/押金页（后端无接口）、菜单/权限管理页、角色绑权限（后端 RoleSaveReq 无 permissionIds）、refreshToken、动态路由、仪表盘统计、用户禁用/拉黑操作、操作日志查询页。

**风险**：
- SPU 编辑表单三层嵌套（SPU→SKU→方案）全量覆盖保存，字段多易错 → 编辑页独立路由 + detail 回填 + 提交前前端校验
- 角色无绑权限接口 → 角色页文案注明二期，避免运营误解
- Windows/MSYS 下 pnpm 命令输出编码偶发乱码，不影响功能

## 六、后端配合项（审查反馈，不阻塞 console）

1. **订单 4 个操作接口（ship/returnSign/acceptCheck/acceptConfirm）未挂 `@SaCheckPermission`**，而权限树已定义 `order:ship`/`order:accept` —— 与商品/设备/账号模块做法不一致，建议后端补注解。
2. t_permission 存量库新增菜单节点不会自动长入（`count()>0` 跳过守卫），后续加菜单需手工补数。
