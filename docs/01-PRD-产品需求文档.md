## 1. 项目背景与定位

**易租（ezu）** 是一个面向 C 端个人用户的**自营设备租赁平台**，租赁品类以电脑、摄像机、打印机等 3C/影像设备为主。

- **定位**：个人完整作品 / 副业项目，按真实产品标准设计与实现，未来可能上线运营
- **模式**：自营——设备为平台自有资产，用户直接向平台租赁，无商户入驻
- **目标用户**：C 端个人（摄影爱好者、短期办公需求、活动拍摄等场景）
- **核心卖点**：信用免押（预留）、按日/周/月灵活租期、AI 智能选品与客服

## 2. 用户角色

| 角色 | 端 | 说明 |
|------|-----|------|
| 租客 | 微信小程序 + 支付宝小程序 | 浏览、下单、支付、收还设备、咨询 AI 助手 |
| 运营/管理员 | Web 管理后台 | 商品、库存、订单、用户、财务、AI 知识库管理 |

## 3. 核心业务闭环

### 3.1 用户侧（交易闭环）

```
浏览选品 → 选租期下单 → 付租金+押金 → 快递收货 → 使用
    → 续租 / 提前买断 / 到期归还 → 寄回设备 → 平台验收 → 退押金 → 评价
```

### 3.2 设备侧（资产闭环）

```
采购入库 → 质检定级 → 上架 → 出租（SN 绑定订单）→ 归还验收
    → 维修/清洁 → 再上架 → …… → 报废
```

**租赁与电商的核心差异**：设备是「借出去还要还回来」的资产，必须做**序列号（SN）级台账**——每台设备在哪个订单、租了多久、修过几次全程可追溯。这是本项目建模的核心。

## 6. 关键状态机

### 6.1 订单状态

```
待支付 → 待发货 → 已发货 → 租赁中 → 归还中（用户寄回）→ 验收中 → 已完成
   │        │        │                              │
   └────────┴────────┴──→ 已取消          （验收不通过 → 定损流程【二期】）
```

### 6.2 设备（SN）状态

```
在库 → 锁定（下单未发货）→ 在租 → 归还验收 → 在库
                维修 ──→ 报废（终态）
```

## 7. 非功能需求与约束

| 项 | 说明 |
|----|------|
| 支付宝信用分 | **本期不实现，仅预留**：支付渠道抽象（PaymentChannel）+ 数据模型预留 |
| 多租户 | 不需要（自营单主体，非 SaaS） |
| 性能 | 个人项目量级，无特殊要求；架构不设分库分表 |
| 部署 | docker-compose 单机部署 |

## 8. 名词表

| 名词 | 含义 |
|------|------|
| SPU | 标准产品单元，如「佳能 EOS R6 Mark II」 |
| SKU | 最小库存/销售单元，如「EOS R6II + 24-105 套机」，挂租金方案 |
| SN | 设备序列号，一台物理实机的唯一标识，资产台账主体 |
| 租约（Lease） | 一次租赁的起止时间约定，支持续租产生新租期段 |
| 押金 | 下单时收取/冻结、验收通过后退还的担保金额 |
| 定损 | 归还验收发现损坏时评估维修费用（二期） |
| 买断 | 租赁期间支付差额买下设备（预留） |
